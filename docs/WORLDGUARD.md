# eSCore и WorldGuard

`eSCore-WorldGuard` — отдельный companion-plugin для интеграции с WorldGuard.

Он нужен не вместо основного `eSCore`, а вместе с ним.

## Зачем сделан отдельный companion

Интеграция с WorldGuard вынесена в отдельный Bukkit-плагин по практической причине:

- некоторые сценарии нужно поднимать отдельно от основного runtime `eSCore`;
- companion должен включаться как обычный плагин Paper/Bukkit;
- внутренние Java-расширения `eSCore` загружаются позже и не всегда подходят для такого сценария.

То есть companion и внутренние `eSCore`-расширения — это разные механизмы.

## Что даёт companion

Основные задачи companion-модуля:

- работа с WorldGuard regions;
- region-aware event routing;
- специальные каналы для JS-скриптов `eSCore`;
- region-based контроль того, разрешён ли учёт событий.

## Артефакт

Companion собирается как отдельный jar:

- `eSCore-WorldGuard`

Его нужно класть в:

- `plugins/`

А не в:

- `plugins/eSCore/extensions/`

## Связь с основным плагином

Схема простая:

- основной модуль: `eSCore`
- companion: `eSCore-WorldGuard`

Оба — обычные Bukkit/Paper плагины.

Companion публикует данные и каналы для основного runtime `eSCore`, а скрипты уже реагируют на них.

## Когда он нужен

Companion полезен, если:

- нужно учитывать события только вне safe-region;
- нужно по-разному обрабатывать события в зависимости от региона;
- нужно давать скриптам WorldGuard-aware payload;
- нужно централизованно решать, считать событие или нет.

## Флаг region tracking

В интеграции используется custom flag:

- `wscore-track`

Это legacy-имя флага, которое часто уже используется в существующих конфигурациях WorldGuard.

Пока оно оставлено как совместимое техническое имя, даже несмотря на ребрендинг проекта в `eSCore`.

Смысл флага остаётся тем же:

- разрешить учёт;
- запретить учёт;
- дать скриптам информацию о tracking-state региона.

## Пример сценария

Например, сервер хочет считать убийства мобов только вне spawn-региона.

Тогда companion:

- получает событие смерти сущности;
- определяет региональную точку;
- смотрит значение tracking flag;
- отправляет подходящий канал в `eSCore`;
- JS-скрипт уже увеличивает или не увеличивает счётчик.

## Каналы для скриптов

Companion-плагин полезен именно тем, что делает worldguard-события удобными для JS runtime.

То есть скрипт получает не «сырое Java API WorldGuard», а уже подготовленные каналы и payload.

Это удобнее для тех случаев, где:

- бизнес-логика должна оставаться в JS;
- интеграционную механику хочется держать в Java;
- нужна читаемая конфигурация скриптов без тяжёлой Java-обвязки.

## Где размещать скрипты

Сами скрипты по-прежнему находятся в:

- `plugins/eSCore/scripts/`

Companion туда ничего не копирует и не хранит.

Он только даёт дополнительный источник событий и контекста.

## Что важно помнить

- `eSCore-WorldGuard` — это отдельный Bukkit-плагин;
- он не является обычным внутренним extension jar для `eSCore`;
- внутренние расширения и companion-плагины — разные уровни интеграции;
- скрипты остаются частью `eSCore`, а не companion-модуля.

## Практическая рекомендация

Используйте companion, если:

- реально нужен region-aware tracking;
- логика зависит от флагов WorldGuard;
- нужно отделить раннюю интеграцию с WorldGuard от общего runtime.

Если таких требований нет, основной `eSCore` можно использовать и без companion-модуля.
