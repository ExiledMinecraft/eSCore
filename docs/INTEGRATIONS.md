# Интеграции eSCore

`eSCore` умеет работать как самостоятельный runtime для скриптов и плейсхолдеров, но при этом предоставляет Java API для интеграций с другими плагинами.

В проекте есть два уровня интеграций:

- встроенные адаптеры, которые поставляются вместе с `eSCore`;
- внешние плагины и расширения, которые используют `eScoreApi`.

## Встроенные интеграции

На текущий момент основной модуль содержит:

- PlaceholderAPI-совместимый слой;
- интеграцию с LuckPerms;
- загрузчик внутренних Java-расширений `eSCore`;
- поддержку companion-плагина для WorldGuard.

Эти интеграции управляются из основного runtime плагина и пересобираются при `/escore reload`.

## Что считается внешней интеграцией

Внешний плагин может:

- зарегистрировать собственный placeholder hook;
- зарегистрировать value provider;
- пробросить Bukkit/Paper событие в канал скриптов;
- читать и изменять значения игроков через API;
- получать доступ к состоянию интеграций и скриптов.

## Основные API-классы

Публичные классы и интерфейсы:

- `eScoreApi`
- `eScoreProvider`
- `eScoreRegistration`
- `eScorePlaceholderHook`
- `eScoreValueProvider`
- `eScoreEventBridge`
- `eScoreExtension`

При написании новых интеграций используйте имена `eScore*`.

Старый бренд `WScore` допустим только там, где нужно сохранить совместимость с уже написанным кодом.

## Получение API

`eSCore` регистрирует `eScoreApi` в Bukkit ServicesManager и дополнительно предоставляет статический доступ через `eScoreProvider`.

Типичная стратегия:

1. попробовать получить сервис из ServicesManager;
2. если сервис ещё не доступен, дождаться включения `eSCore`;
3. не полагаться на жёсткий startup order, если это не нужно.

## Placeholder hooks

`eScorePlaceholderHook` подходит, когда:

- значение удобнее считать в Java, а не в JS;
- placeholder зависит от внешнего API другого плагина;
- нужно скрыть тяжёлую интеграционную логику за одним id.

Хорошие сценарии для placeholder hook:

- `%escore_rank_title%` на основе внешней RPG-системы;
- `%escore_pet_level%` через API плагина питомцев;
- `%escore_region_state%` через стороннюю protection-систему.

## Value providers

`eScoreValueProvider` подходит, когда скриптам нужно получать данные в стиле `hook:<provider>:<key>`.

Это полезно, если:

- Java-плагин отдаёт несколько разных значений;
- нужно переиспользовать одну интеграцию сразу в нескольких скриптах;
- требуется единая нормализация внешних данных перед JS-слоем.

Примеры ключей:

- `hook:luckperms:prefix`
- `hook:luckperms:group`
- `hook:shop:balance`
- `hook:clans:member_count`

## Event bridges

`eScoreEventBridge` нужен, когда Bukkit/Paper событие нужно превратить в script-channel.

Типичный сценарий:

- Java-код слушает событие;
- определяет игрока;
- формирует payload;
- отправляет его в `fireChannelEvent(...)`;
- JS-watch уже обрабатывает канал.

Это позволяет не писать отдельную script-runtime логику на каждое Java событие.

## Внутренние расширения

`eSCore` умеет загружать внутренние Java-расширения из каталога:

- `plugins/eSCore/extensions/`

Расширение реализует `eScoreExtension` и может:

- регистрировать placeholder hooks;
- регистрировать value providers;
- добавлять event bridges;
- выполнять произвольную инициализацию на старте.

Внутреннее расширение — это не то же самое, что внешний PlaceholderAPI expansion.

## PlaceholderAPI-совместимость

Во встроенном PlaceholderAPI-слое используются два namespace:

- основной: `%escore_*%`
- legacy: `%wscore_*%`

Оба ведут к одному и тому же runtime, но в новых интеграциях нужно документировать именно `%escore_*%`.

## Интеграция LuckPerms

Встроенная интеграция с LuckPerms даёт:

- primary group;
- список групп;
- prefix и suffix;
- `meta:<key>`;
- `permission:<node>`;
- script-defined contexts;
- context bridge для значений `eSCore`.

По умолчанию контекстные ключи теперь ориентируются на `escore:*`, а не на `wscore:*`.

## Companion для WorldGuard

Отдельный companion-модуль используется, когда интеграция должна включаться достаточно рано и работать отдельно от внутренних runtime-расширений.

Его стоит рассматривать как отдельный Bukkit-плагин рядом с `eSCore`, а не как обычное внутреннее расширение.

## Когда писать интеграцию на Java, а когда на JS

Пишите на JS, если:

- логика локальная и короткая;
- данные уже доступны внутри `eSCore`;
- реакция на событие не требует внешних API.

Пишите интеграцию на Java, если:

- нужен внешний plugin API;
- важна производительность на горячем пути;
- нужно переиспользование между несколькими скриптами;
- требуется сложная обработка Bukkit/Paper событий.

## Каналы и bridge-события

Если внешний плагин хочет отдать событие скриптам `eSCore`, он обычно делает одно из двух:

- напрямую вызывает `fireChannelEvent(...)`;
- регистрирует `eScoreEventBridge`, чтобы `eSCore` сам подключил listener.

Это удобно, потому что Java-часть отвечает только за извлечение игрока и payload, а бизнес-логика остаётся в скриптах.

## Рекомендации по именованию

Для новых интеграций используйте:

- id в lowercase: `escore`, `luckperms`, `shop`, `clans`;
- namespace `escore`, а не `wscore`;
- Java-имена `eScore*`, а не `WScore*`.

Legacy-имена допустимы только в трёх случаях:

- миграция со старых конфигов;
- совместимость с уже выданными правами;
- работа со старыми script-pack'ами.
